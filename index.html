WebGazer Tool Talk: test site

Team D13 Cactus · CS-3014 Applied HCI. Webcam eye tracking (WebGazer.js) compared with Microsoft Clarity. Video is processed only in this browser. Nothing from the camera is uploaded or recorded.

1. Session

Set this before each run. Every result is saved with it.

2. Run the steps in order

Step 0 · CalibrateLook at each dot and click it 5 times. Redo whenever the person, seat or lighting changes. Step 1 · Big targets2×2 grid, 8 trials. Hit rate is calculated automatically. Step 2 · Small targets6×6 grid, 8 trials. Hit rate is calculated automatically. Task 1 · Pick a storyLarge regions, where it should work. Gaze share per story vs. the click. Task 2 · Find "Sports"Small menu links, where it should fail. Gaze spread across links.

On test pages: D toggles the gaze dot, H toggles the heatmap (after a run), V toggles the camera preview (shows your face, so keep it off while recording). Use full screen (F11) and keep the same window size for every run.

3. Results

Failure-condition protocol

  • glasses / dim light: clear calibration, recalibrate in that condition, then run Step 1 (and Step 2 if time allows).
  • head moved: calibrate normally, then lean back or shift sideways about 20 cm without recalibrating, then run Step 1.
  • Compare each hit rate with that person's baseline.
